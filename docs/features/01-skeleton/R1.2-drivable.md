# The app runs in a browser, an agent can drive it, and the harness can see a failure that throws nothing

## Goal

R1.1 left a repo that installs, lints, typechecks and unit-tests itself, with `expo-sqlite` walled
off. It renders nothing: there is no route tree, `npm run web` has never been run, and
`@playwright/test` is not a dependency. After this ships, `npm run web` serves the app on
`http://localhost:8081`, a route renders a frozen list of transactions an agent can reach by
`testID`, and `npm run e2e` drives that page and exits zero.

The load-bearing half is the harness, not the screen. `AGENTS.md` currently instructs every future
agent to *"collect page errors and assert the list is empty"* - and stage 1 observed that rule
calling a completely dead database clean. When the wasm asset failed to resolve, the page emitted
**no `pageerror` and no console error**; the database promise simply never settled and the UI sat on
loading forever. The only signal was a failed network request. This stack's characteristic failure
is a promise that never settles, not a throw, so a collector built to the letter of the current
contract would certify a broken app as healthy. After this ships the collector sees that class of
failure, it has been **observed catching one**, and `AGENTS.md` says so.

## Out of scope

- **Reading a database.** No `expo-sqlite` call, on any platform. The screen renders an in-memory
  frozen fixture. R1.1's guards remain in force and this spec must not weaken them.
- **The four-state read machine.** `loading` / `ready` / `failed` / `stalled`, the port, the fakes
  and the deadline are Phase 2. This screen has one state: it renders the fixture it was given.
- **Any interaction.** No navigation, no detail view, no add, no edit, no filtering, no scrolling
  behaviour. One route, one list.
- **Styling.** No design system, no theme, no layout work beyond what makes the list legible.
- **Totals.** No sum is displayed. The fixture spans two currencies and `AGENTS.md` forbids a
  cross-currency total without a rate source, so the screen shows rows and no aggregate.
- **Categories and line items.** `line_items` is Phase 3's schema; nothing here renders or derives a
  category.
- **The device leg.** `npm start` stays declared and unrun.
- **CI.** No workflow file, no CI-conditional behaviour.
- **Component-level tests.** No component renderer exists and none is being added, so **anything
  asserted about rendered output is asserted through the browser**, under an `e2e` binding. A
  requirement may still bind `integration` for a seam that is not rendered output - the money
  formatter and the fixture value are read directly, in node.

## Requirements

### R1.2.1 - Playwright is a declared dependency and its browser is available
- **binding:** none
- **Behaviour:** `npm run e2e` runs without any unattended install, in the same way R1.1 made
  `npm run lint` run without one.
- **Acceptance:** `@playwright/test` is in `devDependencies`. Running `npm run e2e` twice leaves
  `package.json` and `package-lock.json` byte-identical to before the first run - this establishes
  that **npm** installed nothing behind the run, and nothing more. The browser binary lives in a
  shared cache **outside the repo**, where no manifest check can see it, so it is covered separately:
  the install is an explicit command stated in `AGENTS.md`'s `## Commands` block, and with the
  browser absent `npm run e2e` **fails with an error naming that command** rather than downloading
  one. Chromium is the only browser this suite requires.

### R1.2.2 - The served page identifies itself as this app
- **binding:** e2e
- **Behaviour:** Anything driving `localhost:8081` can tell this app from another process holding
  that port, and can only tell once application code has actually run.
- **Acceptance:** Loading `/` renders an element with `testID` `app-identity` whose text is exactly
  `personal-finance`. Every journey asserts it **before its own body**, so a stranger on the port
  fails on identity rather than on a confusing downstream assertion. *A bare HTTP 200 is not the
  criterion: the dev server returns an HTML shell before any application code runs, so identity is
  only observable once the page has rendered - which is why this binds `e2e` and not `none`.*

### R1.2.3 - Money is integer minor units carrying a currency, and formats without arithmetic on floats
- **binding:** integration
- **Behaviour:** An amount is an integer count of minor units together with an ISO 4217 code, and
  rendering one produces a string whose digits are exact for every value the type admits.
- **Acceptance:** The formatter takes an **explicit locale**; every criterion below is stated with it
  pinned to `hu-HU`, so no criterion depends on the host's default locale. Write `digits(s)` for the
  string `s` with every non-digit character removed. With the locale pinned:
  - `1200000` / `HUF` produces a string containing `HUF` with `digits = 1200000`
  - `349900` / `EUR` produces a string containing `EUR` with `digits = 349900`
  - `1` / `HUF` produces `digits = 001` and `1` / `JPY` produces `digits = 1` - the minor-unit
    exponent comes from a **per-currency table**, not a hardcoded division by 100. This pair is what
    distinguishes the two; the first two examples are both exponent-2 and cannot.
  - `8905600350800199` / `HUF` produces `digits = 8905600350800199`, i.e. ending `...01.99`. Passing
    through a float yields `...01.98`. *This is the observable form of "no floating point": inside the
    safe-integer range the property is otherwise invisible, and a criterion nobody can check is not a
    criterion. An exact path exists - `Intl.NumberFormat` accepts a `BigInt` or a decimal string - so
    this is satisfiable, not a trap.*

  Group separator, decimal separator, symbol-versus-code and the order of number and currency are
  **user-visible copy and are not asserted here**; they are settled at the human gate. A value whose
  `amountMinor` is not a safe integer, or which carries no `currency`, or whose `currency` is not
  three uppercase letters, is rejected **by throwing**. *This seam never imports `expo-sqlite`, which
  is what permits an `integration` binding.*

### R1.2.4 - The fixture is valid under the money rule, and is fixed
- **binding:** integration
- **Behaviour:** The frozen fixture the screen renders obeys the repo's own conventions and is the
  same on every run, so it cannot be the thing that makes a later assertion wrong.
- **Acceptance:** Every fixture row has an integer `amountMinor`, a three-uppercase-letter
  `currency`, a **non-empty** `merchant`, an ISO 8601 `occurredAt` that parses, and an `id` unique
  within the fixture. The fixture spans **at least two distinct currencies**, so the
  currency-carrying invariant is exercised rather than assumed. Two criteria make "fixed" checkable
  rather than a claim about how the file was written:
  - every `occurredAt` is strictly earlier than `2025-01-01T00:00:00Z` - a value derived from the
    clock cannot satisfy this, which is what a "not relative to now" criterion has to mean to be
    testable at all
  - the test asserts the **exact set of `id`s against literals written in the test**, so a generated
    or clock-derived id fails rather than passing whatever it produced

### R1.2.5 - The route renders every fixture transaction, reachable by `testID`
- **binding:** e2e
- **Behaviour:** Loading `/` shows the fixture's transactions, each individually addressable by an
  agent, with every row present at once.
- **Acceptance:** The page renders an element with `testID` `txn-list` containing one element per
  fixture row, each with `testID` `txn-<id>`. For at least one row, its rendered text contains that
  row's `merchant` and its formatted amount. The number of rendered rows equals the number of
  fixture rows **with no scrolling**: the list is not virtualised, and every row is in the DOM at the
  suite's fixed viewport. *A virtualised list would make the count viewport-dependent, and scrolling
  behaviour is out of scope, so there is no scroll available to make the missing rows appear.* A row
  renders the merchant and the formatted amount and nothing else in this phase; `occurredAt` is
  carried in the fixture and not displayed.

### R1.2.6 - The harness collects failed requests as well as thrown errors
- **binding:** e2e
- **Behaviour:** The Playwright harness gathers uncaught page errors, console errors **and failed
  network requests** into one fault list, obtained the same way by every spec.
- **Acceptance:** A **fault** is an uncaught page error, a console message at `error` level, or a
  request that failed with a network-level error or completed with an HTTP status of 400 or above.
  Requests aborted by navigation (`net::ERR_ABORTED`) and the dev server's own HMR and websocket
  traffic are **not** faults - a collector that fires on those becomes noise and gets muted, which is
  worse than not having one. Two different spec files obtain the fault list from the same shared
  fixture, **neither declaring a collector of its own**, and R1.2.7 proves the list one of them
  receives actually works. The happy-path journey asserts its fault list is empty, and does so
  **after its last action**, so a fault arriving late is still caught. *R1.2.7's self-test is not a
  journey and deliberately asserts a non-empty list; "every journey asserts empty" is scoped to
  journeys.*

### R1.2.7 - The collector has been observed catching a failure that throws nothing
- **binding:** e2e
- **Behaviour:** The fault list is demonstrated non-empty for a failure that emits no `pageerror` and
  no console error - the exact class of failure that made the current contract's rule unsafe.
- **Acceptance:** A test drives the page so that a request fails in a way R1.2.6 counts as a fault,
  while producing no uncaught error and no console error, and asserts the collector's fault list
  contains an entry **identifying that request by URL**. **This is the anti-vacuity requirement of the
  spec.** Without it, the collector is the same unbacked claim `AGENTS.md` already made: a harness
  nobody has watched fail is not evidence of anything. *Two of R1.1's three guards were proven the
  same way, by breaking them.*

### R1.2.8 - Playwright collects only the browser suite
- **binding:** integration
- **Behaviour:** Playwright's collection is confined to `e2e/`, completing the disjointness claim
  whose jest half R1.1 already enforces.
- **Acceptance:** A check asks Playwright which files it would collect and asserts the list is
  non-empty and every path is under `e2e/`. To avoid the vacuity R1.1 hit from the other side, it
  also plants a file outside `e2e/` that Playwright's default patterns would otherwise collect, asks
  again, and asserts it is still absent, then removes it. *This check never imports `expo-sqlite`.*

### R1.2.9 - `npm run e2e` brings up what it needs and exits zero
- **binding:** none
- **Behaviour:** The e2e command is self-sufficient: it starts the web server itself rather than
  assuming someone already did.
- **Acceptance:** With nothing listening on 8081 and the browser already installed per R1.2.1,
  `npm run e2e` exits 0 and its journeys run. The command starts the web target itself and waits for
  `http://localhost:8081` to answer HTTP 200, allowing **at least 120 seconds**, because stage 1
  observed a first-ever Metro bundle exceeding 30 seconds and a default that fails once per machine
  teaches people to rerun - which is how real failures get reflexively rerun too. If a server is
  already listening, the run either uses it or fails on identity per R1.2.2, and never reports a
  result about a different app.

### R1.2.10 - The contract stops asserting a rule that certified a dead app as healthy
- **binding:** none
- **Behaviour:** `AGENTS.md` describes the collector this phase actually built, and records what
  Phases 0 and 1 learned about this stack.
- **Acceptance:** Four named sections change.
  - `## Validating your work` requires collecting failed requests alongside page and console errors.
  - `## Learnings` gains an entry recording that this stack's characteristic failure is a promise
    that never settles rather than a throw; that `expo-sqlite`'s web backend has foreign keys **off
    by default** and reports the generic `Error finalizing statement` when one is violated; and that
    `jest` cannot execute `expo-sqlite` at all, its node preset returning empty results from a shim.
  - `## Commands` gains the browser-install command of R1.2.1.
  - `## Unverified on web - the standing list` gains `Intl` behaviour on Hermes, which this spec's
    own Unverified section says belongs there by name.

  Every claim in `## Validating your work` that is **not yet true** is marked as such rather than
  left reading as fact: the seeded fixture, the engine fakes, and - because the four-state read
  machine is explicitly out of scope here - the distinction between a read that never settles, an
  empty result and a failed read. *That distinction is Phase 2's to build; recording it now as a
  contract claim would repeat exactly the defect this requirement exists to remove.*

### R1.2.11 - The existing checks still pass over the new tree
- **binding:** none
- **Behaviour:** Adding `app/`, `e2e/` and a Playwright config does not break what R1.1 established.
- **Acceptance:** With those present, `npm run lint`, `npm run typecheck` and `npm test` each exit 0.
  R1.1's three guards in `lib/guards/` pass **unmodified** - `sqlite-confined` now has real source
  under its scan roots for the first time, and `jest-excludes-e2e` now runs with `e2e/` actually
  existing. *This phase is the first to add files under those roots, and `tsconfig.json` currently
  limits `types` to node and jest, so "the suite still passes" is a claim that has to be checked
  rather than assumed.*

## Edge cases

- **A failure that emits nothing.** The whole reason for R1.2.7. Observed in stage 1: a wasm asset
  failed to resolve, `openDatabaseAsync()` neither resolved nor rejected, and the page produced no
  `pageerror` and no console error. A collector watching only thrown errors reports it as clean.
- **Port 8081 held by another process.** Expo shifts to a different port rather than failing, which
  would silently defeat a URL-specific check, and a reused server may not be this app at all.
  Handled by R1.2.2, which binds `e2e` precisely so something actually executes the identity check:
  a stranger on the port fails on identity, and a shifted port fails on connection.
- **The first-ever Metro bundle exceeds 30 seconds.** Observed. The server start gets at least 120s
  (R1.2.9).
- **Playwright's collection check is vacuously true.** `e2e/` will contain specs, so its own half is
  not vacuous - but "every path is under `e2e/`" would stay green if the scope were widened and
  nothing outside existed to collect. R1.2.8 plants a file outside to give it something to fail on.
- **The harness is bypassed by a spec that forgets it.** R1.2.6 requires two spec files to obtain the
  list from one shared fixture, because the thing it must catch is the thing nobody remembers to
  wire by hand.
- **Console noise that is not a failure.** Only console messages at error level count; warnings do
  not.
- **Request noise that is not a failure.** The mirror of the above, and the one the original draft
  missed: navigations abort in-flight requests and the dev server keeps an HMR websocket, so a
  collector that counts every `requestfailed` flakes on the happy path. R1.2.6 defines a fault
  narrowly enough that R1.2.7's induced failure still counts.
- **A list that renders only what fits.** A virtualised list satisfies "one element per row" only
  for the rows in view, and scrolling is out of scope, so the count assertion would silently measure
  the viewport. R1.2.5 forbids virtualisation for this fixture.
- **`npm run e2e` triggering an unattended browser download.** The failure mode R1.1 spent a whole
  commit preventing for eslint. The manifest byte-identity check does **not** prove this, because the
  browser cache is outside the repo; R1.2.1 covers it by requiring an explicit install command and a
  run that fails, naming that command, when the browser is missing.
- **A fixture date relative to now.** Would make a rendered assertion time-dependent. R1.2.4's
  pre-2025 cutoff is what makes that checkable, since a clock-derived value cannot pass it.
- **The screen imports `expo-sqlite`.** R1.1's two guards remain in force and this spec adds source
  files under their scan roots for the first time, so the confinement guard finally has real code to
  cover. R1.2.11 binds that claim to an actual check.

## Known-open notes

Recorded from the machine pass, in the order the reader reported them. **These do not block** and
are not being fixed to get through the gate; the implementer reads them once.

1. **R1.2.1** - which browsers must be installed was unspecified. *Round 1 fixed this to Chromium
   only while resolving a blocking finding; the note is kept for the record.*
2. **R1.2.9** - calling `npm run e2e` self-sufficient sits oddly beside a browser install a person
   must run first, so "exits 0 with nothing listening" is not reproducible on a virgin machine
   without that precondition.
3. **R1.2.7** - inducing the failure with Playwright's own request interception risks a tautology
   that asserts only that Playwright emits `requestfailed`, and Chromium logs some resource failures
   to the console, which could make the no-console-error half unachievable.
4. **R1.2.8** - nothing covers cleanup of the planted file if the check crashes mid-run, nor its
   interaction with R1.1's `jest-excludes-e2e` guard, which plants its own file and will now find
   `e2e/` already existing.
5. **spec-wide** - four requirements bind `none`, so nothing re-checks them after this sitting, in a
   spec whose own thesis is that an unbacked claim is the defect.
6. **R1.2.10** - `AGENTS.md`'s `## Pipeline` block still says to bring the stack up with `npm run web`
   first while also saying a bare `npm run e2e` starts it; `## Pipeline` is not among the sections
   R1.2.10 corrects.
7. **R1.2.1** - no requirement addresses Playwright reporter configuration, and the default HTML
   reporter's open-on-failure behaviour can block a non-interactive run.
8. **R1.2.3** - the behaviour says ISO 4217 while the acceptance only checks three uppercase letters,
   so `ZZZ` passes.
9. **R1.2.6** - when the fault assertion runs relative to the journey was unstated. *Round 1 fixed
   this to "after its last action" while resolving a blocking finding.*
10. **R1.2.2** - `personal-finance` is user-visible copy on the app's only screen, and whether
    `app-identity` may be visually hidden is unstated while `AGENTS.md` escalates unspecified copy.
11. **R1.2.5** - the per-row `testID` derivation was unstated. *Round 1 fixed this to `txn-<id>`.*
12. **R1.2.1** - R1.2.1 and R1.2.10 both require the browser-install command in `## Commands`,
    duplicating one fact across two requirements.
13. **spec-wide** - no requirement pins e2e determinism: retries, workers, viewport, locale or
    timezone, although Phase 0's evidence standard was ten consecutive fresh-context runs.
14. **R1.2.2** - the declared script is `expo start --web`, which runs an interactive terminal UI and
    opens a browser tab of its own, and nothing says what that does when Playwright's `webServer`
    spawns it on every run.
15. **R1.2.7** - the shape of a fault-list entry is only partly defined. *Round 1 fixed the
    identifying field to the URL while resolving a blocking finding; the entry's full shape is still
    the implementer's.*
16. **spec-wide** - the fixture is called "frozen" but no requirement asserts immutability of the
    exported value.

## Unverified

- **The device leg.** `npm start` is declared and never run. Nothing here says anything about iOS or
  Android, and the standing unverified list applies in full.
- **`expo-sqlite` on any platform.** No database is opened. R1.1's guards prove the import cannot be
  reached; nothing here proves the library works. That is Phase 3's, and Phase 0 already measured the
  backend separately.
- **`Intl` behaviour on Hermes.** Money formatting pins a locale and may use `Intl`, so device
  behaviour may diverge from web - Android ships a partial `Intl`. The web target proves nothing
  about it, and R1.2.10 puts it on the standing unverified list by name.
- **Whether the identity element survives a production web export.** Only the dev server is
  exercised; `expo export` is not run.
- **Real cold-start time on a virgin machine.** The 120s allowance is headroom, not a measurement.
- **The cross-family gate verdict.** No working `OPENROUTER_API_KEY` exists on this machine, so this
  spec is read on the in-harness route only: fresh context, same model family.
