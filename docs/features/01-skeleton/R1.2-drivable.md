# The app runs in a browser, an agent can drive it, and the harness can see a failure that throws nothing

## Goal

R1.1 left a repo that installs, lints, typechecks and unit-tests itself, with `expo-sqlite` walled
off. It renders nothing: there is no route tree, `npm run web` has never been run, and
`@playwright/test` is not a dependency. After this ships, `npm run web` serves the app on
`http://localhost:8081`, a route renders a frozen list of transactions an agent can reach by
`testID`, and `npm run e2e` drives that page and exits zero.

The load-bearing half is the harness, not the screen. `AGENTS.md` currently instructs every future
agent to *"collect page errors and assert the list is empty"* - and stage 1 observed that rule
calling a completely dead database clean. When the wasm asset failed to resolve, the page emitted
**no `pageerror` and no console error**; the database promise simply never settled and the UI sat on
loading forever. The only signal was a failed network request. This stack's characteristic failure
is a promise that never settles, not a throw, so a collector built to the letter of the current
contract would certify a broken app as healthy. After this ships the collector sees that class of
failure, it has been **observed catching one**, and `AGENTS.md` says so.

## Out of scope

- **Reading a database.** No `expo-sqlite` call, on any platform. The screen renders an in-memory
  frozen fixture. R1.1's guards remain in force and this spec must not weaken them.
- **The four-state read machine.** `loading` / `ready` / `failed` / `stalled`, the port, the fakes
  and the deadline are Phase 2. This screen has one state: it renders the fixture it was given.
- **Any interaction.** No navigation, no detail view, no add, no edit, no filtering, no scrolling
  behaviour. One route, one list.
- **Styling, and human-facing number presentation.** No design system, no theme, no layout work
  beyond what makes the list legible. **Amounts render as an exact decimal string and a currency
  code** - grouping separators, currency symbols and locale-aware formatting are deliberately not
  built here. They are user-visible copy; `AGENTS.md` says that is escalated, and the human pass is
  the escalation.
- **What a row shows beyond the merchant and the amount.** `occurredAt` is carried in the fixture and
  not displayed in this phase. This is a scope statement, not an acceptance criterion - "renders
  nothing else" is not objectively checkable and is not asserted.
- **Totals.** No sum is displayed. The fixture spans two currencies and `AGENTS.md` forbids a
  cross-currency total without a rate source, so the screen shows rows and no aggregate.
- **Categories and line items.** `line_items` is Phase 3's schema; nothing here renders or derives a
  category.
- **The device leg.** `npm start` stays declared and unrun.
- **CI.** No workflow file, no CI-conditional behaviour.
- **Component-level tests.** No component renderer exists and none is being added, so **anything
  asserted about rendered output is asserted through the browser**, under an `e2e` binding. A
  requirement may still bind `integration` for a seam that is not rendered output - the money
  formatter and the fixture value are read directly, in node.

## Requirements

### R1.2.1 - Playwright is a declared dependency and its browser install is documented
- **binding:** none
- **Behaviour:** `npm run e2e` runs without any unattended install, in the same way R1.1 made
  `npm run lint` run without one.
- **Acceptance:** `@playwright/test` is in `devDependencies`, and Chromium is the only browser the
  suite requires. `npm run e2e` leaves `package.json` and `package-lock.json` byte-identical to before
  it ran - this establishes that **npm** installed nothing behind the run, and nothing more. *An
  earlier draft ran it twice, which quietly depended on the first run's Expo server releasing port
  8081 through the intervening `npm run` wrapper; under R1.2.9's refusal to reuse a server, an
  orphan would fail the second run for reasons having nothing to do with the manifest. One run
  checks the same thing without that coupling.* The browser binary lives in a machine-wide cache **outside the repo**, where
  no check this suite can safely run would see it: the install is an explicit command stated in
  `AGENTS.md`'s `## Commands` block, and that is the whole of the requirement. *An earlier draft also
  demanded the run fail with an error naming that command. Producing the "browser absent" condition
  means deleting a machine-wide cache that other repos share, so that criterion could not be checked
  without a destructive setup - it is recorded as a known-open note instead of pretended to.*

### R1.2.2 - The served page identifies itself as this app
- **binding:** e2e
- **Behaviour:** Anything driving `localhost:8081` can tell this app from another process holding
  that port, and can only tell once application code has actually run.
- **Acceptance:** Loading `/` renders an element with `testID` `app-identity` whose text is exactly
  `personal-finance`, **which is `app.json`'s `slug`** - the element renders that value rather than a
  second copy of the string, so the app's declared identity and the assertion cannot drift apart.
  **The shared fixture of R1.2.6 hands a spec an already-opened page by
  default** - navigated, with this assertion already made - so a journey gets identity without opting
  in and cannot forget it. The unnavigated page is available only by asking for it **by a different
  name**, which R1.2.7 is the only spec to do. *Both halves of that matter: an earlier draft made
  every journey call an open step, which is an opt-in a spec can forget, and the draft before it had
  the fixture navigate unconditionally, which left R1.2.7 nowhere to inject a load-time failure.
  Defaulting to opened and naming the opt-out is what satisfies both.* *A bare HTTP 200 is not the
  criterion: the dev server returns an HTML shell before any application code runs, so identity is
  only observable once the page has rendered - which is why this binds `e2e` and not `none`.*

### R1.2.3 - An amount's exact value renders as a decimal string, without float arithmetic
- **binding:** integration
- **Behaviour:** An amount is an integer count of minor units together with an ISO 4217 code. A pure
  function turns one into an exact decimal string. How that string is later dressed for a human is
  presentation, and is not settled here.
- **Acceptance:** The function returns a **plain decimal string**: ASCII digits, an optional leading
  `-`, and a `.` separating major from minor units when the currency has minor units. **The table below
  is the criterion**, and it is stated in locale-free output, so it fails on its own for any
  implementation routed through the host locale - `hu-HU` renders `12 000,00`, not `12000.00`. *That
  is why no separate "calls no `Intl`" clause is needed: an unchecked claim about source text is
  replaced by output the table already pins.*

  | `amountMinor` | `currency` | result |
  |---|---|---|
  | `1200000` | `HUF` | `12000.00` |
  | `349900` | `EUR` | `3499.00` |
  | `1` | `HUF` | `0.01` |
  | `1` | `JPY` | `1` |
  | `-50` | `EUR` | `-0.50` |
  | `8905600350800199` | `HUF` | `89056003508001.99` |

  The `HUF`/`JPY` pair is the discriminating one: exponent 2 against exponent 0, which a hardcoded
  division by 100 fails. The last row is the observable form of "no floating point" - a float path
  yields `...01.98`. Inside the safe-integer range the property is otherwise invisible, and a
  criterion nobody can check is not a criterion.

  The exponent comes from a per-currency table whose authority is **ISO 4217**, the standard
  `AGENTS.md` already names. **This differs from CLDR/ICU for `HUF`**, which treats the app's own
  primary currency as zero-decimal. The divergence is real and deliberate, and it is flagged for the
  human pass rather than settled here.

  Rejected **by throwing**: an `amountMinor` that is not a safe integer, a `currency` that is not
  three uppercase letters, and a well-formed code that is absent from the table. *Silence is the
  failure mode being avoided - `Intl` formats an unknown code at two decimals without complaint.*

  This module imports nothing from `react-native` or `expo-*`, so jest and Playwright can both load
  it under a plain TypeScript loader. *This seam never imports `expo-sqlite`, which is what permits an
  `integration` binding.*

### R1.2.4 - The fixture is valid under the money rule, and is fixed
- **binding:** integration
- **Behaviour:** The frozen fixture the screen renders obeys the repo's own conventions and is the
  same on every run, so it cannot be the thing that makes a later assertion wrong.
- **Acceptance:** Every fixture row has:
  - an `amountMinor` that is a **safe integer**, in the domain R1.2.3 accepts rather than the one it
    throws on
  - a `currency` of three uppercase letters that is **present in R1.2.3's table**
  - a **non-empty** `merchant`
  - an `occurredAt` matching `YYYY-MM-DDTHH:MM:SSZ` **by pattern**, not merely by parsing - `Date.parse`
    accepts a great deal that is not ISO 8601
  - an `id` unique within the fixture and matching `^[a-z0-9-]+$`, because the same value becomes a
    `testID` and a literal inside a browser selector

  The fixture spans **at least two distinct currencies**, so the currency-carrying invariant is
  exercised rather than assumed. Two criteria make "fixed" checkable rather than a claim about how
  the file was written: every `occurredAt` is strictly earlier than `2025-01-01T00:00:00Z`, which no
  clock-derived value can satisfy; and the test asserts the **exact set of `id`s against literals
  written in the test**, so a generated id fails rather than passing whatever it produced. This
  module imports nothing from `react-native` or `expo-*`.

### R1.2.5 - The route renders every fixture transaction, reachable by `testID`
- **binding:** e2e
- **Behaviour:** Loading `/` shows the fixture's transactions, each individually addressable by an
  agent, with every row present at once.
- **Acceptance:** The page renders an element with `testID` `txn-list` containing one element per
  fixture row, each with `testID` `txn-<id>`. **For every row**, its rendered text contains that row's
  `merchant`, that row's `amountMinor` rendered by R1.2.3, and that row's `currency` - not "for at
  least one row", which a screen that gets every other row wrong would still satisfy. Because R1.2.3
  takes no locale, this assertion does not depend on the browser's. **Every row's element is present
  in the DOM without scrolling** - asserted per row, by its own `testID`, not as a count. *That
  per-row assertion is what makes virtualisation fail, and it is observable where "the list is not
  virtualised" was not: a count comparison passes for a virtualised list whenever the fixture happens
  to fit the viewport, and the implementer chooses both.*

### R1.2.6 - The harness collects failed requests as well as thrown errors
- **binding:** e2e
- **Behaviour:** The Playwright harness gathers uncaught page errors, console errors **and failed
  network requests** into one fault list, obtained the same way by every spec, and watching from
  before the first navigation.
- **Acceptance:** A shared fixture attaches its listeners **before any navigation** - the stage-1
  failure this phase exists to catch happened during initial load, so a collector wired after
  `page.goto` would miss the very thing it is for. It offers two entry points over the same collector:
  an **opened page** (the default, navigated and identity-asserted per R1.2.2) and an **unopened
  page** (collector attached, nothing loaded) that a spec must name explicitly. The happy-path journey
  takes the default and cannot forget identity; the collector self-test takes the unopened one,
  installs its interception, and navigates itself.

  **The suite has two journeys** - the happy path and the collector self-test - and each `e2e`
  requirement is covered by the one it is grouped into: R1.2.2, R1.2.5 and this requirement by the
  happy path, R1.2.7 by the self-test. *An earlier draft called the self-test "not a journey", which
  contradicted what `binding: e2e` means - covered by the journey it is grouped into.* **The fault
  list is created per test**, not shared across the run, so the happy path's "empty" assertion cannot
  be affected by the self-test's deliberately non-empty one. Every fault entry carries **which channel
  saw it** (page error, console, or request) and the URL where one applies.

  A fault is an uncaught page error, a console message at `error` level, or a request that failed or
  returned HTTP 400 or above, **minus an exclusion set the implementer owns**. The spec does not
  enumerate that set, because the last draft's attempt to - `net::ERR_ABORTED`, HMR, websockets - was
  both unenforceably vague and incomplete, missing ordinary dev-server 404s for `/favicon.ico` and
  source maps. It is pinned from **both sides instead**, which is checkable where a list of URL
  patterns is not:
  - the happy-path journey's fault list is **empty** on a healthy app (this requirement), so an
    exclusion set that is too narrow fails
  - the induced load-time failure is still **caught** (R1.2.7), so an exclusion set that is too wide
    fails

  Two different spec files obtain the list from that one fixture. The happy-path journey asserts its
  list is empty **after its last action**, so a fault arriving late is still caught. *The empty
  assertion belongs to the happy-path journey specifically; the self-test asserts the opposite, which
  is the whole of R1.2.7.*

### R1.2.7 - The collector has been observed catching a failure that throws nothing
- **binding:** e2e
- **Behaviour:** The fault list is demonstrated non-empty for a failure that emits no uncaught error
  - the exact class of failure that made the current contract's rule unsafe.
- **Acceptance:** A test takes the **unopened** page of R1.2.6, installs its interception, and
  navigates itself, causing a request to fail **during initial page load** while producing no
  uncaught page error. It asserts the fault list contains an entry whose channel is **the request
  channel** and whose URL is the one that failed. *Because this spec does not go through the opened
  default, the induced failure is under no obligation to leave `app-identity` rendering - it may
  break the page as thoroughly as it likes, which is what keeps the requirement satisfiable. An
  earlier draft required a request the load makes but identity does not need, and no such request
  was established to exist.* **This is the anti-vacuity requirement of the spec.** Without
  it, the collector is the same unbacked claim `AGENTS.md` already made: a harness nobody has watched
  fail is not evidence of anything. *Two of R1.1's three guards were proven the same way, by breaking
  them.*

  The criterion asserts **no uncaught page error**, and deliberately does not also require no console
  error: Chromium logs some failed resource loads to the console itself, which would make the
  requirement unsatisfiable for reasons that have nothing to do with the app. Asserting the catching
  channel is what preserves the point - it proves the request channel did the work, not the console
  one.

### R1.2.8 - Playwright collects only the browser suite
- **binding:** integration
- **Behaviour:** Playwright's collection is confined to `e2e/`, completing the disjointness claim
  whose jest half R1.1 already enforces.
- **Acceptance:** A check asks Playwright which files it would collect and asserts the list is
  non-empty and every path is under `e2e/`. To avoid the vacuity R1.1 hit from the other side, it
  plants a file matching **the configured `testMatch` of R1.2.9**, at `test-fixtures/gate-plant.spec.ts`, asks
  again, asserts it is still absent, and removes it in a `finally`. That location is chosen so a
  crash cannot damage anything: `test-fixtures/` is **already in jest's `testPathIgnorePatterns`**, so
  a leftover plant cannot pollute `npm test`, while a widened Playwright scope would still reach it -
  which is the only thing the plant is there to detect.

  Because this check binds `integration` and therefore runs inside `npm test`, listing **must not
  start a web server or bind a port**: `npm test` passes unchanged with a dev server already
  listening on 8081, and starting one there would collide with R1.2.9's refusal to reuse. *This check
  never imports `expo-sqlite`.*

### R1.2.9 - `npm run e2e` brings up its own server and exits zero
- **binding:** none
- **Behaviour:** The e2e command is self-sufficient and always tests the working tree: it starts the
  web server itself rather than assuming, or adopting, one that is already there.
- **Acceptance:** With nothing listening on 8081 and the browser already installed per R1.2.1,
  `npm run e2e` exits 0 and its journeys run. The command starts the web target **by running
  `npm run web` itself** and waits for **exactly `http://localhost:8081`** to answer - which is what
  binds the goal's claim about `npm run web` to a check, and what makes Expo silently shifting to
  another port a failure rather than a different green run. It allows **at least 120 seconds**,
  because stage 1 observed a
  first-ever Metro bundle exceeding 30 seconds and a default that fails once per machine teaches
  people to rerun - which is how real failures get reflexively rerun too.

  It **does not reuse an already-running server** (`reuseExistingServer: false`), so an existing
  process on 8081 makes the run fail rather than silently report a green result about stale code.
  *Identity (R1.2.2) does not cover this on its own: a stale server of this same app passes an
  identity check while serving code that is not the working tree. Not reusing is what closes it, and
  it also removes the run's dependence on `CI` being set, which is what that setting defaults to.*

  **`forbidOnly` is set unconditionally**, not derived from an environment variable, so a stray
  `test.only` fails the run rather than quietly reducing the suite to one test and still reporting
  success - the same vacuity R1.1 closed on the jest side. *An earlier draft also claimed "a run in
  which no test executed exits non-zero". That is broader than `forbidOnly` backs - a suite that is
  entirely skipped, or a filter matching nothing, is not covered - so the claim is narrowed to what
  the named mechanism actually delivers, and the remainder is recorded as open.*

  **The reporter is non-interactive.** Playwright's default HTML reporter opens and serves a report on
  failure unless `CI` is set, which would leave a failing `npm run e2e` hanging instead of exiting -
  the opposite of the agent-drivable harness this phase exists to build, and a re-introduction of the
  `CI`-dependence this requirement removes elsewhere.

  The config pins the run's environment so criteria elsewhere can depend on it: **`testDir` is
  `e2e/`**, which is what R1.2.8's "every path is under `e2e/`" is measured against; **a single
  Chromium project**, which is where R1.2.1's "Chromium is the only browser" becomes a fact about the
  configuration rather than an unchecked claim; and **one worker, no retries, and a fixed viewport**.
  Its `testMatch` is narrowed to `*.spec.ts`, which also keeps Playwright's listing away from R1.1's
  `jest-excludes-e2e` guard, whose planted `e2e/planted.test.ts` matches Playwright's *default*
  pattern while containing a bare `it(...)` that would throw on load.

  **The run leaves nothing listening on 8081.** The server it started is torn down with the run,
  including when the run fails, so a second `npm run e2e` in the same session succeeds. Without this
  the refusal to reuse turns an orphaned child into a failure of the *next* run, for reasons having
  nothing to do with the app. The server is spawned with piped, non-TTY stdio and must reach ready
  under it - `expo start --web` otherwise runs an interactive terminal UI and opens a browser tab of
  its own.

### R1.2.10 - The contract stops asserting a rule that certified a dead app as healthy
- **binding:** none
- **Behaviour:** `AGENTS.md` describes the collector this phase actually built, and records what
  Phases 0 and 1 learned about this stack.
- **Acceptance:** Five named sections change.
  - `## Validating your work` requires collecting failed requests alongside page and console errors,
    and its "How to run the app end-to-end" instruction stops telling agents to start `npm run web`
    and leave it running - under R1.2.9 that guarantees the next `npm run e2e` fails on a held port.
  - `## Learnings` gains an entry recording that this stack's characteristic failure is a promise
    that never settles rather than a throw; that `expo-sqlite`'s web backend has foreign keys **off
    by default** and reports the generic `Error finalizing statement` when one is violated; and that
    **`jest` cannot exercise `expo-sqlite` at all - its node preset resolves the module to a shim
    that returns empty results, so a query test passes green against no database.** *That wording
    matters: the danger is not that it fails, it is that it succeeds.*
  - `## Commands` gains the browser-install command of R1.2.1.
  - `## Unverified on web - the standing list` gains `Intl` behaviour on Hermes, which this spec's
    own Unverified section says belongs there by name.
  - `## Pipeline`'s `e2e:` line stops telling agents to bring the stack up with `npm run web` first.
    R1.2.9 makes `npm run e2e` start its own server and refuse to reuse one, so following the current
    instruction would guarantee the failure it was written to prevent.

  **Three named claims** in `## Validating your work` are marked as not yet true rather than left
  reading as fact: the seeded fixture, the engine fakes, and - because the four-state read machine is
  explicitly out of scope here - the distinction between a read that never settles, an empty result
  and a failed read. *An earlier draft said "every claim that is not yet true", which quantifies over
  an unenumerated set and asks a checker to judge each sentence. Three named ones can be checked.* *That distinction is Phase 2's to build; recording it now as a
  contract claim would repeat exactly the defect this requirement exists to remove.*

### R1.2.11 - The existing checks still pass over the new tree
- **binding:** none
- **Behaviour:** Adding `app/`, `e2e/` and a Playwright config does not break what R1.1 established.
- **Acceptance:** With those present, `npm run lint`, `npm run typecheck` and `npm test` each exit 0,
  **and still do after `npm run e2e` has run.** That second half is not decoration: an e2e run writes
  bundled JavaScript into `playwright-report/` and `test-results/`, `.gitignore` covers them but
  `eslint.config.js` does not, and ESLint 9's flat config does not read `.gitignore` - so both
  directories join eslint's `ignores`, exactly as `test-fixtures/` already has. Without it
  `npm run lint` passes or fails depending on whether e2e ran first.
  R1.1's three guards in `lib/guards/` pass **unmodified** - `sqlite-confined` now has real source
  under its scan roots for the first time, and `jest-excludes-e2e` now runs with `e2e/` actually
  existing. *This phase is the first to add files under those roots, and `tsconfig.json` currently
  limits `types` to node and jest, so "the suite still passes" is a claim that has to be checked
  rather than assumed.*

## Edge cases

- **A failure that emits nothing.** The whole reason for R1.2.7. Observed in stage 1: a wasm asset
  failed to resolve, `openDatabaseAsync()` neither resolved nor rejected, and the page produced no
  `pageerror` and no console error. A collector watching only thrown errors reports it as clean.
- **A collector that starts watching too late.** The stage-1 failure happened during initial load, so
  a fixture wiring its listeners after `page.goto` would satisfy every other criterion and miss the
  one class of failure this phase exists for. R1.2.6 requires attachment before any navigation.
- **Port 8081 held by another process.** Expo shifts to a different port rather than failing, which
  would silently defeat a URL-specific check. R1.2.2's identity element catches a stranger;
  R1.2.9's refusal to reuse a server catches the subtler case, **a stale instance of this same app**,
  which passes identity while serving code that is not the working tree.
- **The first-ever Metro bundle exceeds 30 seconds.** Observed. The server start gets at least 120s.
- **Playwright's collection check is vacuously true.** `e2e/` will contain specs, so its own half is
  not vacuous - but "every path is under `e2e/`" would stay green if the scope were widened and
  nothing outside existed to collect. R1.2.8 plants a file to give it something to fail on, at a path
  jest already ignores so a crashed run cannot pollute `npm test`.
- **The harness is bypassed by a spec that forgets it.** R1.2.6 requires two spec files to obtain the
  list from one shared fixture, because the thing it must catch is the thing nobody remembers to
  wire by hand. R1.2.2's identity assertion rides the same fixture for the same reason.
- **Console noise that is not a failure.** Only console messages at error level count; warnings do
  not.
- **Request noise that is not a failure.** Navigations abort in-flight requests, the dev server keeps
  an HMR websocket, and it answers 404 for `/favicon.ico` and for source maps. Enumerating those in
  the spec was tried and was both vague and incomplete; R1.2.6 pins the exclusion set from both
  sides instead - too narrow fails the happy path, too wide fails R1.2.7.
- **A list that renders only what fits.** A virtualised list satisfies a row *count* whenever the
  fixture happens to fit the viewport, and the implementer picks both, so the count proves nothing.
  R1.2.5 asserts each row's element by its own `testID` instead, which a virtualised list fails on
  the first row it drops.
- **A failing run that hangs instead of exiting.** Playwright's default HTML reporter opens and
  serves a report on failure unless `CI` is set. An agent driving `npm run e2e` would wait forever on
  the one outcome it most needs to see. R1.2.9 requires a non-interactive reporter.
- **A suite that runs no tests.** Playwright exits 0 when every test is skipped, and `forbidOnly`
  is on only under `CI` by default, so a stray `test.only` would shrink the suite to one test and
  still report success - the exact vacuity R1.1 closed on the jest side. R1.2.9 sets `forbidOnly`
  unconditionally, which covers the stray `test.only`. It does **not** cover a wholly skipped suite
  or a filter matching nothing; that remainder is known-open note 39 rather than a claim the spec
  makes.
- **Playwright's listing colliding with R1.1's own planted file.** `jest-excludes-e2e` plants
  `e2e/planted.test.ts` holding a bare `it(...)`, which matches Playwright's *default* pattern and
  would throw on load if a listing ran while the plant existed - a nondeterministic `npm test`
  failure. R1.2.9 narrows `testMatch` to `*.spec.ts`, which the plant does not match.
- **The self-test breaking the page it also has to identify.** Resolved by construction rather than
  by constraint: R1.2.7 takes the fixture's *unopened* page and navigates itself, so it never goes
  through the identity assertion and may break the page as thoroughly as it likes. An earlier draft
  required the induced failure to spare `app-identity`, which depended on a request the load makes
  but identity does not need - and no such request was established to exist on a Metro dev server.
- **The two currency authorities disagree.** ISO 4217 gives `HUF` exponent 2; CLDR/ICU treats it as
  zero-decimal. Every criterion in R1.2.3 changes depending on which is chosen, and it is this app's
  primary currency. R1.2.3 names ISO 4217 and flags the divergence for the human pass.
- **An unknown but well-formed currency code.** `Intl` formats `ZZZ` at two decimals without error, so
  the platform default here is silent and wrong. R1.2.3 throws instead.
- **A negative amount.** Refunds exist. R1.2.3 carries the sign, and a criterion asserts it, because
  an earlier draft compared only digit characters and would have accepted a formatter that dropped
  the minus sign.
