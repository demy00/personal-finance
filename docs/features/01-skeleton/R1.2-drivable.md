# The app runs in a browser, an agent can drive it, and the harness can see a failure that throws nothing

## Goal

R1.1 left a repo that installs, lints, typechecks and unit-tests itself, with `expo-sqlite` walled
off. It renders nothing: there is no route tree, `npm run web` has never been run, and
`@playwright/test` is not a dependency. After this ships, `npm run web` serves the app on
`http://localhost:8081`, a route renders a frozen list of transactions an agent can reach by
`testID`, and `npm run e2e` drives that page and exits zero.

The load-bearing half is the harness, not the screen. `AGENTS.md` currently instructs every future
agent to *"collect page errors and assert the list is empty"* - and stage 1 observed that rule
calling a completely dead database clean. When the wasm asset failed to resolve, the page emitted
**no `pageerror` and no console error**; the database promise simply never settled and the UI sat on
loading forever. The only signal was a failed network request. This stack's characteristic failure
is a promise that never settles, not a throw, so a collector built to the letter of the current
contract would certify a broken app as healthy. After this ships the collector sees that class of
failure, it has been **observed catching one**, and `AGENTS.md` says so.

## Out of scope

- **Reading a database.** No `expo-sqlite` call, on any platform. The screen renders an in-memory
  frozen fixture. R1.1's guards remain in force and this spec must not weaken them.
- **The four-state read machine.** `loading` / `ready` / `failed` / `stalled`, the port, the fakes
  and the deadline are Phase 2. This screen has one state: it renders the fixture it was given.
- **Any interaction.** No navigation, no detail view, no add, no edit, no filtering, no scrolling
  behaviour. One route, one list.
- **Styling.** No design system, no theme, no layout work beyond what makes the list legible.
- **Totals.** No sum is displayed. The fixture spans two currencies and `AGENTS.md` forbids a
  cross-currency total without a rate source, so the screen shows rows and no aggregate.
- **Categories and line items.** `line_items` is Phase 3's schema; nothing here renders or derives a
  category.
- **The device leg.** `npm start` stays declared and unrun.
- **CI.** No workflow file, no CI-conditional behaviour.
- **Component-level tests.** No component renderer exists and none is being added, so every rendering
  requirement here binds `e2e`.

## Requirements

### R1.2.1 - Playwright is a declared dependency and its browser is available
- **binding:** none
- **Behaviour:** `npm run e2e` runs without any unattended install, in the same way R1.1 made
  `npm run lint` run without one.
- **Acceptance:** `@playwright/test` is in `devDependencies`. Running `npm run e2e` twice leaves
  `package.json` and `package-lock.json` byte-identical to before the first run. The browser binary
  the suite needs is obtained by a documented command that is stated in `AGENTS.md`'s `## Commands`
  block, not by a step someone has to remember.

### R1.2.2 - `npm run web` serves the app, and says which app it is
- **binding:** none
- **Behaviour:** The web target starts and answers, and anything reading `localhost:8081` can tell
  this app from another process holding that port.
- **Acceptance:** With port 8081 free, `npm run web` responds with HTTP 200 at
  `http://localhost:8081` within 120 seconds of starting. Loading that page in a browser renders an
  element with `testID` `app-identity` whose text is exactly `personal-finance`. *"Exits zero" is not
  the criterion for a long-running server, and a bare 200 is not either - the dev server returns an
  HTML shell before any application code runs, so identity is only observable once the page has
  rendered.*

### R1.2.3 - Money is integer minor units carrying a currency, and formats without arithmetic on floats
- **binding:** integration
- **Behaviour:** An amount is an integer count of minor units together with an ISO 4217 code, and
  rendering one produces a string without ever converting through a floating-point number.
- **Acceptance:** Given 1200000 and `HUF`, formatting produces a string containing a grouped
  `12 000` and the currency; given 349900 and `EUR`, one containing `3 499` and its currency. A value
  that is not an integer, or carries no currency code, or carries a code that is not three uppercase
  letters, is rejected rather than rendered. The exact rendered wording is user-visible copy and is
  settled at the human gate, not here; what is fixed is that the arithmetic is integer-only and the
  currency is always present. *This seam never imports `expo-sqlite`, which is what permits an
  `integration` binding.*

### R1.2.4 - The fixture is valid under the money rule
- **binding:** integration
- **Behaviour:** The frozen fixture the screen renders obeys the repo's own conventions, so it cannot
  be the thing that makes a later assertion wrong.
- **Acceptance:** Every fixture row has an integer `amountMinor`, a three-uppercase-letter currency
  code, an ISO 8601 `occurredAt` that parses, and an id unique within the fixture. The fixture spans
  **at least two distinct currencies**, so the currency-carrying invariant is exercised rather than
  assumed. Dates are fixed literals, not relative to now, so an assertion on rendered content is
  reproducible.

### R1.2.5 - The route renders every fixture transaction, reachable by `testID`
- **binding:** e2e
- **Behaviour:** Loading `/` shows the fixture's transactions, each individually addressable by an
  agent.
- **Acceptance:** The page renders an element with `testID` `txn-list` containing one element per
  fixture row, each with a `testID` derived from that row's id. For at least one row, its rendered
  text contains that row's merchant and its formatted amount. The number of rendered rows equals the
  number of fixture rows.

### R1.2.6 - The harness collects failed requests as well as thrown errors
- **binding:** e2e
- **Behaviour:** The Playwright harness gathers uncaught page errors, console errors **and failed
  network requests** into one fault list that every journey asserts is empty.
- **Acceptance:** The e2e suite exposes a shared harness rather than a per-spec preamble - a
  collector each spec has to remember to wire up is one a spec will eventually forget. The happy-path
  journey asserts its fault list is empty.

### R1.2.7 - The collector has been observed catching a failure that throws nothing
- **binding:** e2e
- **Behaviour:** The fault list is demonstrated non-empty for a failure that emits no `pageerror` and
  no console error - the exact class of failure that made the current contract's rule unsafe.
- **Acceptance:** A test drives the page in a way that produces a failed network request while
  producing no uncaught error and no console error, and asserts the collector's fault list contains
  it. **This is the anti-vacuity requirement of the spec.** Without it, the collector is the same
  unbacked claim `AGENTS.md` already made: a harness nobody has watched fail is not evidence of
  anything. *Two of R1.1's three guards were proven the same way, by breaking them.*

### R1.2.8 - Playwright collects only the browser suite
- **binding:** integration
- **Behaviour:** Playwright's collection is confined to `e2e/`, completing the disjointness claim
  whose jest half R1.1 already enforces.
- **Acceptance:** A check asks Playwright which files it would collect and asserts the list is
  non-empty and every path is under `e2e/`. To avoid the vacuity R1.1 hit from the other side, it
  also plants a file outside `e2e/` that Playwright's default patterns would otherwise collect, asks
  again, and asserts it is still absent, then removes it. *This check never imports `expo-sqlite`.*

### R1.2.9 - `npm run e2e` brings up what it needs and exits zero
- **binding:** none
- **Behaviour:** The e2e command is self-sufficient: it starts the web server itself rather than
  assuming someone already did.
- **Acceptance:** With nothing listening on 8081, `npm run e2e` exits 0 and its journeys run. The
  server start is allowed at least 120 seconds, because stage 1 observed a first-ever Metro bundle
  exceeding 30 seconds and a default that fails once per machine teaches people to rerun - which is
  how real failures get reflexively rerun too. If a server is already listening, the run either uses
  it or fails on identity per R1.2.2, and never reports a result about a different app.

### R1.2.10 - The contract stops asserting a rule that certified a dead app as healthy
- **binding:** none
- **Behaviour:** `AGENTS.md` describes the collector this phase actually built, and records what
  Phases 0 and 1 learned about this stack.
- **Acceptance:** `## Validating your work` requires collecting failed requests alongside page and
  console errors, and states that a read which never settles is a distinct outcome from an empty
  result and from a failed read. `## Learnings` gains an entry recording that this stack's
  characteristic failure is a promise that never settles rather than a throw; that `expo-sqlite`'s
  web backend has foreign keys **off by default** and reports the generic `Error finalizing
  statement` when one is violated; and that `jest` cannot execute `expo-sqlite` at all, its node
  preset returning empty results from a shim. `## Commands` gains the browser-install command of
  R1.2.1. The two claims in `## Validating your work` that remain forward-looking - the seeded
  fixture and the engine fakes - are marked as not yet true rather than left reading as fact.

## Edge cases

- **A failure that emits nothing.** The whole reason for R1.2.7. Observed in stage 1: a wasm asset
  failed to resolve, `openDatabaseAsync()` neither resolved nor rejected, and the page produced no
  `pageerror` and no console error. A collector watching only thrown errors reports it as clean.
- **Port 8081 held by another process.** Expo shifts to a different port rather than failing, which
  would silently defeat a URL-specific check, and a reused server may not be this app at all.
  Handled by R1.2.2's identity element: a stranger on the port fails on identity, and a shifted port
  fails on connection.
- **The first-ever Metro bundle exceeds 30 seconds.** Observed. The server start gets at least 120s
  (R1.2.9).
- **Playwright's collection check is vacuously true.** `e2e/` will contain specs, so its own half is
  not vacuous - but "every path is under `e2e/`" would stay green if the scope were widened and
  nothing outside existed to collect. R1.2.8 plants a file outside to give it something to fail on.
- **The harness is bypassed by a spec that forgets it.** R1.2.6 requires a shared harness rather than
  a preamble, because the thing it must catch is the thing nobody remembers to wire by hand.
- **Console noise that is not a failure.** A collector that treats every console message as a fault
  becomes noise and gets muted, which is worse than not having one. Only console messages at error
  level count; warnings do not.
- **`npm run e2e` triggering an unattended browser download.** The failure mode R1.1 spent a whole
  commit preventing for eslint. R1.2.1 requires the install be a documented command, and the
  byte-identity check is what proves nothing installed itself behind the run.
- **A fixture date relative to now.** Would make a rendered assertion time-dependent and the fixture
  non-reproducible. R1.2.4 requires fixed literals.
- **The screen imports `expo-sqlite`.** R1.1's two guards remain in force and this spec adds source
  files under their scan roots for the first time, so the confinement guard finally has real code to
  cover.

## Unverified

- **The device leg.** `npm start` is declared and never run. Nothing here says anything about iOS or
  Android, and the standing unverified list applies in full.
- **`expo-sqlite` on any platform.** No database is opened. R1.1's guards prove the import cannot be
  reached; nothing here proves the library works. That is Phase 3's, and Phase 0 already measured the
  backend separately.
- **`Intl` behaviour on Hermes.** If money formatting uses `Intl`, device behaviour may diverge from
  web - Android ships a partial `Intl`. The web target proves nothing about it, and it belongs on the
  standing unverified list by name.
- **Whether the identity element survives a production web export.** Only the dev server is
  exercised; `expo export` is not run.
- **Real cold-start time on a virgin machine.** The 120s allowance is headroom, not a measurement.
- **The cross-family gate verdict.** No working `OPENROUTER_API_KEY` exists on this machine, so this
  spec is read on the in-harness route only: fresh context, same model family.
